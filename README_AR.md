# ابوناصر — abbeedo · الموقع 2.1

الموقع **ابوناصر / abbeedo 2.1.5** في `/`، وصفحة التطبيقات في `/apps`، والتطبيق **ابوناصر TV / abbeedo TV 1.2.4** في `/app`. إصدار الموقع مستقل عن إصدارات البرامج: مصدر Windows **1.2.1** وAPK أندرويد **3.9.4** ضمن مدخلات النشر.

الأصل الإنتاجي هو **https://www.abbeedo.com**؛ يحوّل إليه `https://abbeedo.com`. إضافة الرئيسية `/` إلى الشاشة الرئيسية تبقيها اختصارًا للموقع باسم ابوناصر. لتثبيت PWA التطبيق افتح `/app` وأضفه من هناك باسم ابوناصر TV وشعاره. رابط «الرئيسية» داخل نسخة المتصفح يعيد إلى الموقع.

## الحالة المتحققة في 20 نوفمبر 2026

- الموقع والتطبيق **منشوران على الدومين الحي**؛ إيصال المراجعة المتحققة في `validation/hosting-status-2.1.json`، على فريق Vercel **abbeedo** ومشروعه الحالي **abbeedo-tv-1.1**.
- مخزن **Private Vercel Blob** باسم `abbeedo-tv-private` أُنشئ وربط بالمشروع. أعاد [فحص الخدمة الحية](https://www.abbeedo.com/api/health) **200** مع `storage: true` و`mediaConfigured: true`. مشكلة `503 HOSTING_CONFIG` السابقة عولجت.
- [abbeedo7/abbeedo-site](https://github.com/abbeedo7/abbeedo-site) مستودع **Public** متاح؛ مشكلة الوصول العامة السابقة عولجت. يحتوي هذا المصدر على إعداد `.github/workflows/publish-release.yml` لإصدار التنزيلات.
- اكتمل الإصدار العام [build-1-1-cdf83058](https://github.com/abbeedo7/abbeedo-site/releases/tag/build-1-1-cdf83058)، وتعمل روابط APK وEXE من مستودعك. يجب التحقق من نجاح Actions والبيان والأصول الأربعة عند كل إصدار جديد.
- لم يحدث اختبار تثبيت أو تحديث على أجهزة Windows أو LG أو Samsung فعلية، ولم تُعتمد حزم المتاجر. نجاح health يؤكد إعداد الخدمات؛ دخول اشتراك مصرح به وتشغيل محتواه يحتاجان اختبارًا فعليًا.

## اتصال الآيفون بمصدر HTTP — الخادم 2.1.5

يبقى تطبيق الويب 1.2.4 والبرامج الأصلية بإصداراتها الحالية؛ التعديل على خدمات Vercel ويعمل عند الطلب التالي دون إعادة تثبيت التطبيق. عند رفض المصدر المهيأ اتصال Vercel بـ403 مصنفًا، تمر طلباته عبر خدمة التشغيل القديمة المملوكة للحساب، دون تغيير الخدمة القديمة أو نقل بياناتها. يبقى تحليل القوائم المتدرج في الخادم الحالي.

يُفعّل `CLIENT_FALLBACK_ORIGIN` على الخادم فقط ويقبل عنوان الخدمة المملوكة المثبت في الكود دون أي عنوان بديل. لا يضيف متصفح العميل حساب ChatGPT أو خطوة تسجيل جديدة. التنزيلات تبقى من GitHub. لا تُمرر كوكيز المتصفح أو رؤوس الدخول إلى الخدمة؛ بيانات اشتراك المصدر تمر بطلب HTTPS مخصص إلى خدمة المالك القائمة. لا تُكتب البيانات في السجلات أو روابط الوسيط العامة.

روابط HLS والمقاطع والمفاتيح وطلبات Range وHEAD تمر من أصل الموقع نفسه بروابط AES-GCM محددة المدة ومقيدة بالأصل. تبقى سياسة المصدر وقوائم المضيفين والتشفير والبيانات الحالية محفوظة. غياب الإعداد أو فشل الخدمة لا يصنع تسجيل دخول ناجحًا أو يتجاوز رفض الحساب.

نجح تشغيل فيديو الاختبار العام فعليًا في Chromium وWebKit، مع فحص المقاطع والنطاقات والتشفير والإلغاء. نجح وصول رد API الحقيقي للمصدر عبر الخدمة المملوكة باستخدام حساب اختبار عشوائي غير صالح، وأعاد رفض الحساب الصحيح بدل رفض الاستضافة. لم تُستخدم بيانات عميل حقيقية ولم يحدث اختبار على آيفون فعلي. تعتمد الخدمة على توافر خدمة التشغيل المملوكة الحالية؛ لا يوجد ادعاء بسعة غير محدودة.

## إصلاحات الدخول والتنزيل 2.1.4

Windows **1.2.1** يتصل بمصدر الاشتراك من جهاز العميل عبر طبقة أصلية محدودة، ويشغّل الوسائط عبر روابط محلية مبهمة مع تحقق المصدر وطلبات Range. يلزم ترقية النسخة الأصلية للحصول على هذه القدرة؛ تحديث الواجهة وحده لا يضيفها إلى Windows 1.2.0. نجح 58 اختبارًا أصليًا وفحص Electron فعلي على Linux ببيانات اختبار، دون حساب عميل أو جهاز Windows فعلي.

تجهز روابط التنزيل رابط الملف العام الرسمي على الخادم، ثم تحول الزائر مباشرة إلى CDN أصول GitHub دون المرور بصفحة GitHub أو تطبيقه؛ لا يلزم حساب GitHub للتحميل. الملفات تبقى في Releases العامة للمستودع نفسه.

في 2.1.4 كان مصدر HTTP يرفض اتصال Vercel بـ403. أضاف إصدار الخادم 2.1.5 المسار البديل المبيّن أدناه؛ لا يعني نجاح فحص الخدمة اختبار بيانات اشتراك العميل الفعلية.

## إصلاحات المظهر والتحديث 2.1.3

يطبق سكربت متزامن اللون المحفوظ قبل إنشاء عناصر الواجهة. عند ترقية عميل يملك Service Worker قديمًا، تحمل جميع وحدات التطبيق وروابط CSS وmanifest بصمة البناء لتجاوز الملفات القديمة فورًا؛ العامل الجديد يفحص الشبكة قبل الرجوع إلى كاش الواجهة الحالي. يبقى كاش المشاهدة دون اتصال محفوظًا.

يبقى تطبيق الشاشة الرئيسية بهويته `/app` وبداية تشغيله، ويغطي نطاقه `/` لمنع خروج رابط الرئيسية إلى حاوية أخرى. هوية اختصار الموقع `/website` ونمط المتصفح مستقلان. تحمل روابط الرئيسية والتطبيق لونًا عامًا ووقت الانتقال فقط، وتستهلكهما تهيئة المظهر ثم تزيلهما من العنوان؛ لا تنقل روابط المظهر بيانات الاشتراك.

## النشر والتحديث

المالك اعتمد اختبار التعديلات المطلوبة ثم نشرها على الدومين نفسه ضمن المهمة عند توفر صلاحية Vercel. استخدم مشروع **abbeedo-tv-1.1** القائم؛ النشر المباشر عبر Vercel متاح، وربط Git مفيد للتحديث التلقائي وحفظ المصدر والإصدارات.

للنشر من Git، تحقّق في **Settings → Git** من ربط المستودع الحالي وفرع الإنتاج `main`. دفع المصدر إلى الفرع المرتبط يشغّل بناء Vercel. إعداداته: **Other**، وNode.js **22**، و`npm ci` للتثبيت، و`npm run build` للبناء؛ ينتج البناء `.vercel/output`.

احتفظ بالدومين والمخزن ومتغيرات البيئة ومفاتيح التشفير والجلسات وبيانات المستخدمين. لا تستبدل المخزن أو تدوّر المفاتيح عند تحديث عادي. لا ترفع `.env` أو `.vercel` أو الشهادات أو كلمات المرور أو `node_modules` أو `windows/dist` أو EXE إلى Git. راجع [دليل النشر والتعافي](docs/DEPLOY_2_1_AR.md) و[الخطوات من الآيفون](docs/IPHONE_DEPLOY_AR.md).

## Windows وأندرويد والتلفزيون

يلزم تثبيت Windows **1.2.1** مرة أولى للحصول على المحدّث الأصلي. بعدها ينزّل التطبيق **Setup** جديدًا ويتحقق من الإصدار والحجم وبصمة SHA-256 قبل تشغيل المثبت بموافقة المستخدم. النسخة المحمولة تستخدم Setup عند التحديث؛ لا تستبدل EXE المحمول أثناء تشغيله. ملفات Windows غير موقعة رقميًا.

يلزم تثبيت أندرويد **3.9.4** أول مرة للحصول على مسار التحديث الجديد. يفحص التطبيق البصمة والحزمة والتوقيع قبل فتح مثبت أندرويد؛ تبقى موافقة النظام وإذن تثبيت التطبيقات غير المعروفة عند طلبهما. راجع [تحديث أندرويد](docs/ANDROID_UPDATES_AR.md).

LG ملف IPK حقيقي. Samsung ملف WGT يضم الواجهة كاملة، لكنه **غير موقّع** ويحتاج شهادتي المالك Samsung **author** و**distributor** ثم التوقيع والاختبار. راجع [حالة نسخ التلفزيون](docs/TV_STORES_AR.md).

## البناء محليًا

```sh
npm ci
npm run build
npm test
npm run dev
```

المعاينة على `http://127.0.0.1:9020`. مصدر الموقع في `src/` و`public/`، والتطبيق في `application/`، وخدمات الإصدار والتنزيل في `api/`، ومصدر Windows في `windows/`. التشغيل المحلي لخدمات الحساب والمشاهدة يحتاج إعداد بيئة خاصًا؛ لا تضع أسراره في المصدر العام.

الآيفون يستخدم PWA من `/app`، وليس ملف IPA موقعًا. تختلف الترميزات وDRM وPiP وإشعارات النظام والعمل في الخلفية والتنزيلات حسب المنصة والمصدر؛ يلزم اختبار الأجهزة الفعلية.

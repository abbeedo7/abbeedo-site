# الدومين والتحديثات — 2.1

الأصل الإنتاجي المعتمد **https://www.abbeedo.com**، ويحوّل إليه `https://abbeedo.com`. احتفظ بهذا الترتيب ومشروع Vercel الحالي ومخزن Blob ومفاتيح التشفير والجلسات؛ بيانات المتصفح مرتبطة بالأصل، واستبدال التخزين أو المفاتيح قد يقطع الوصول إلى البيانات السابقة.

الموقع **ابوناصر / abbeedo 2.1.0** في `/` و`/apps`، والتطبيق **ابوناصر TV / abbeedo TV 1.2.0** في `/app`. إضافة الرئيسية إلى الشاشة الرئيسية تبقيها موقعًا؛ تثبيت التطبيق يبدأ من `/app` ويستخدم اسم التطبيق وشعاره. رابط «الرئيسية» داخل نسخة المتصفح يرجع إلى الموقع.

## الحالة الحالية — 20 نوفمبر 2026

الموقع والتطبيق **منشوران** بالمراجعة `web-c4d68d97eb2c7944` على فريق Vercel **abbeedo** ومشروع **abbeedo-tv-1.1**. مخزن **Private Vercel Blob** باسم **abbeedo-tv-private** متصل. أعاد https://www.abbeedo.com/api/health الحالة **200** و`storage: true` و`mediaConfigured: true`؛ عولج خطأ التخزين السابق.

المستودع **https://github.com/abbeedo7/abbeedo-site** عام ومتاح. يحتوي المصدر على Windows **1.2.0** وAPK أندرويد **3.9.4** ومهمة إصدار التنزيلات. نشر ملفات البرامج العامة يحتاج نجاح Actions وظهورها في Releases؛ لا يُستنتج من نجاح نشر الموقع.

## تحديث الموقع والتطبيق

اعتمد المالك اختبار التغييرات المطلوبة ثم نشرها مباشرة عبر Vercel على المشروع والدومين القائمين ضمن المهمة عند توفر الوصول. في النشر من Git، تحقّق من ربط المستودع الحالي بـ **Settings → Git** وفرع الإنتاج `main`؛ دفع المصدر إلى الفرع المرتبط يبني الموقع وواجهة `/app` والخدمات على الدومين نفسه.

إعدادات البناء: Node.js **22**، و`npm ci` ثم `npm run build`. البناء يولد `.vercel/output`. بعد النشر تحقّق من المراجعة الحية ومن health. احتفظ بالموارد والمتغيرات القائمة؛ النشر المعتاد لا يحتاج مخزنًا أو مفاتيح جديدة. للتعافي عند فقد اتصال مورد، راجع [دليل النشر](DEPLOY_2_1_AR.md)؛ ولإدارة التحديث من Safari راجع [دليل الآيفون](IPHONE_DEPLOY_AR.md).

الواجهة المفتوحة تتحقق من نسختها أثناء الاستخدام وتطبّق التحديث عند الخمول أو تعرض طلب تحديث. تبقى التفضيلات على الأصل نفسه. تحديث الويب لا ينشئ حزمة Windows أو Android أو Samsung جديدة.

## تحديث ملفات التنزيل

إعداد التشغيل يقرأ بيان مستودعك العام:

https://github.com/abbeedo7/abbeedo-site/releases/latest/download/releases.json

مهمة `.github/workflows/publish-release.yml` تبني Windows **1.2.0** وتتحقق من APK أندرويد **3.9.4** المرفق ثم تنشر الملفات وبيانها. تعمل عند تحديث مصدر `main`، أو وسم `v*`، أو يدويًا من **Actions → Publish application downloads → Run workflow**. تستثني `docs/**` و`README_AR.md` من إعادة بناء البرامج. عند أول نشر تحقق من نجاح المهمة والأصول الأربعة كما في [دليل الإصدارات](RELEASES_GITHUB_AR.md).

| الوجهة | الرابط الثابت |
| --- | --- |
| Android وAndroid TV وGoogle TV | https://www.abbeedo.com/downloads/android.apk |
| مثبت Windows | https://www.abbeedo.com/downloads/windows.exe |
| Windows المحمول | https://www.abbeedo.com/downloads/windows-portable.exe |

باركودات `abbeedo.com` الحالية تبقى صالحة بتحويلها إلى `www`. البيان يحدد الإصدارات والأحجام والبصمات. التنزيل النهائي من المستودع وأصول GitHub الرسمية؛ عند غياب إصدار صالح يظهر عدم توفر التنزيل. تغذية Android هي `https://www.abbeedo.com/updates.json`، وWindows يقرأ `/api/releases`.

يلزم تثبيت Windows **1.2.0** أول مرة لإضافة المحدّث الأصلي. بعد ذلك ينزّل التطبيق Setup ويتحقق من الحجم وبصمة SHA-256 قبل التثبيت بموافقة المستخدم. المحمول يستخدم Setup أيضًا ولا يستبدل EXE أثناء تشغيله. الملفات غير موقعة ولم تُختبر على جهاز Windows فعلي.

أندرويد يحتاج تثبيت **3.9.4** أول مرة لمسار التحديث الجديد، ثم موافقة مثبت النظام وإذن تثبيت التطبيقات غير المعروفة عند طلبهما. تحديث ملف APK يتطلب رفع الملف الجديد وتحديث بياناته وبصمته؛ راجع [تحديث أندرويد](ANDROID_UPDATES_AR.md).

## التحقق على الأجهزة

نجاح health يؤكد إعداد الخدمات، ويليه اختبار دخول اشتراك مصرح باستخدامه وتشغيله فعليًا. تختلف الترميزات وDRM والإشعارات والعمل في الخلفية حسب الجهاز والمصدر.

لم تُختبر أجهزة Windows أو LG أو Samsung الفعلية ولم تُعتمد حزم المتاجر. LG حزمة IPK حقيقية؛ Samsung حزمة WGT كاملة غير موقعة تحتاج شهادتي المالك author وdistributor ثم التوقيع والاختبار. التفاصيل في [دليل التلفزيون](TV_STORES_AR.md).

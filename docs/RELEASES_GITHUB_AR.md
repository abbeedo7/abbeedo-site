# تنزيل التطبيقات من مستودعك

مصدر تنزيلات التشغيل في `release-config.json` هو المستودع العام **https://github.com/abbeedo7/abbeedo-site** وتحويلات GitHub الرسمية لخوادم أصوله.

في **20 نوفمبر 2026** أصبح المستودع **Public** ومتاحًا، والموقع **2.1.0** والتطبيق **1.2.0** منشوران على **https://www.abbeedo.com** بالمراجعة `web-c4d68d97eb2c7944`. إعداد مصدر Windows **1.2.0** وAPK أندرويد **3.9.4** ومهمة النشر موجود في هذا المستودع. لا يُعتمد اكتمال أول إصدار تنزيلات إلا بعد نجاح المهمة وظهور أصوله العامة؛ نشر Vercel مستقل عن نشر Releases.

## أول تشغيل والتحقق

1. افتح [Actions](https://github.com/abbeedo7/abbeedo-site/actions) وفعّل workflows إن طلب GitHub ذلك. ملف المهمة هو `.github/workflows/publish-release.yml`.
2. إن لم تبدأ المهمة تلقائيًا من دفع المصدر، اختر **Publish application downloads → Run workflow → main → Run workflow**.
3. انتظر نجاح التنفيذ، ثم افتح [Releases](https://github.com/abbeedo7/abbeedo-site/releases). تحقق من إصدار **عام** يحتوي الأصول الأربعة:

   - `abbeedo-TV-Android.apk`
   - `abbeedo-TV-Setup.exe`
   - `abbeedo-TV-Portable.exe`
   - `releases.json`

تبني المهمة Windows **1.2.0** من المصدر، وتتحقق من بصمة APK أندرويد **3.9.4** و`versionCode: 29` مقابل `release-assets/android.json` ثم ترفقه. لا تعيد بناء Android أو تغيّر توقيعه. يبقى الإصدار مسودة حتى رفع الملفات الأربعة، ثم يُنشر كأحدث إصدار. تستخدم Actions توكن GitHub المؤقت؛ لا تنسخ قيمته إلى المصدر أو إعدادات التنزيل العامة.

عند فشل المهمة، افتح سجل الخطوة الفاشلة وأصلح السبب ثم أعد التشغيل. لا تضف EXE أو `windows/dist` إلى سجل Git ولا تعتبر مسودة ناقصة إصدارًا متاحًا. مصدر Windows وAPK المدقق وبياناته هي مدخلات البناء؛ الأسرار وشهادات التوقيع و`node_modules` و`.vercel` خارج المستودع العام.

إرشادات تحديث المصدر والنشر في [دليل نشر 2.1](DEPLOY_2_1_AR.md)، وخطوات Safari في [دليل الآيفون](IPHONE_DEPLOY_AR.md).

## كيف تصل التحديثات؟

تقرأ خدمات الموقع البيان العام الثابت:

https://github.com/abbeedo7/abbeedo-site/releases/latest/download/releases.json

يضم البيان إصدار كل منصة وحجم الملف وبصمة SHA-256. يتحقق الخادم من البيان والمستودع ومسارات الملفات قبل توجيه الزائر إلى أصول الإصدار نفسه. لا يستطيع الزائر اختيار مستودع أو مضيف تنزيل آخر. قراءة البيان العام لا تحتاج مفتاح GitHub في Vercel أو طلبًا إلى GitHub API.

تشغّل تعديلات مصدر `main` أو وسوم `v*` المهمة تلقائيًا، ويمكن تشغيلها يدويًا. تستثني `docs/**` و`README_AR.md` من إعادة بناء البرامج. تغيير APK يحتاج ملفًا جديدًا وتحديث بياناته وبصمته؛ تعديل الويب لا ينتج إصدار Android جديدًا. تغيير كود أصلي يحتاج زيادة إصدار المنصة وبناء ملفها.

الموقع وواجهة `/app` ينشرهما Vercel مباشرة على المشروع الحالي أو عند دفع Git إلى فرع الإنتاج المرتبط. يلزم نجاح نشر الموقع ونشر الإصدار حتى يعرض الدومين التغييرات المطلوبة وملفاتها الجديدة.

| الوجهة | الرابط الثابت |
| --- | --- |
| أندرويد للجوال والتلفزيون | https://www.abbeedo.com/downloads/android.apk |
| مثبت Windows | https://www.abbeedo.com/downloads/windows.exe |
| Windows المحمول · EXE واحد | https://www.abbeedo.com/downloads/windows-portable.exe |

تبقى باركودات `abbeedo.com` الحالية صالحة عبر التحويل إلى `www.abbeedo.com`. تفحص صفحة التنزيل الإصدارات أثناء الاستخدام، ويعيد رابط التنزيل قراءة البيان عند الطلب. إذا لم يوجد إصدار عام صالح، يظهر `DOWNLOAD_UNAVAILABLE` بدل تنزيل ملف من مضيف آخر.

تغذية Android هي **https://www.abbeedo.com/updates.json** وتشير إلى رابط أندرويد الثابت على الدومين. Windows يقرأ `/api/releases` للحصول على إصدار المثبت وحجمه وبصمته ورابط أصله الموثوق.

## التثبيت الأول والتلفزيون

يلزم تنزيل وتثبيت Windows **1.2.0** مرة أولى للحصول على المحدّث الأصلي. بعدها ينزّل التطبيق Setup للإصدار اللاحق ويتحقق من الحجم وSHA-256 قبل تشغيله بموافقة المستخدم. المحمول يستخدم Setup للتحديث أيضًا ولا يستبدل EXE أثناء تشغيله. ملفات Windows غير موقعة، ولم يُختبر التثبيت أو التحديث على جهاز Windows فعلي.

يلزم تثبيت أندرويد **3.9.4** مرة أولى لمسار التحديث الجديد. يفحص التطبيق البصمة والحزمة والتوقيع ثم يفتح مثبت النظام؛ تبقى موافقة أندرويد وإذن تثبيت التطبيقات غير المعروفة عند طلبهما. راجع [دليل تحديث أندرويد](ANDROID_UPDATES_AR.md).

LG وSamsung خارج أصول مهمة التنزيلات الأربعة. LG حزمة IPK حقيقية، وSamsung حزمة WGT كاملة غير موقعة تحتاج شهادتي المالك author وdistributor ثم التوقيع والاختبار ومراجعة المتجر. التفاصيل في [دليل التلفزيون](TV_STORES_AR.md).

مخزن الحسابات **Private Vercel Blob** متصل بالفعل؛ أعاد فحص health الحي **200** مع `storage: true` و`mediaConfigured: true`. احتفظ بالمخزن ومتغيراته ومفاتيحه الحالية. نجاح health أو الإصدار لا يثبت نجاح اشتراك مزود فعلي أو تطابق قدرات جميع الأجهزة؛ يلزم اختبار الدخول والتشغيل والمنصات الفعلية.

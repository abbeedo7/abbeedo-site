# نشر ابوناصر 2.1 وتحديثه

الموقع **ابوناصر / abbeedo 2.1.0** والتطبيق **ابوناصر TV / abbeedo TV 1.2.0** منشوران على **https://www.abbeedo.com**. يحوّل `https://abbeedo.com` إلى هذا الأصل. Windows في المصدر **1.2.0** وAPK أندرويد المرفق **3.9.4**.

## الإعداد الحالي — 20 نوفمبر 2026

- فريق Vercel: **abbeedo**؛ المشروع القائم: **abbeedo-tv-1.1**.
- المراجعة المنشورة على الدومين: `web-c4d68d97eb2c7944`.
- مخزن **Private Vercel Blob** باسم **abbeedo-tv-private** متصل ببيئة الإنتاج؛ أعاد `/api/health` الحالة **200** و`storage: true` و`mediaConfigured: true`.
- المستودع [abbeedo7/abbeedo-site](https://github.com/abbeedo7/abbeedo-site) **Public** ومتاح. زالت مشكلة الوصول السابقة؛ لا يلزم إنشاء مستودع أو مشروع أو مخزن بديل.
- إعداد إصدار التنزيلات موجود في `.github/workflows/publish-release.yml`. لا يُعتمد نجاح أول إصدار Windows/APK إلا بعد نجاح Actions وظهور الأصول العامة.

اعتمد المالك اختبار التعديلات المطلوبة ثم نشرها مباشرة على مشروع Vercel الحالي ضمن المهمة عند توفر الوصول. GitHub ليس شرطًا للنشر المباشر للموقع؛ يُستخدم لحفظ المصدر وإصدارات البرامج، وللنشر التلقائي متى كان ربط Git مفعّلًا.

## التحديث المعتاد

1. عدّل المصدر الحالي مع الحفاظ على `package.json` و`vercel.json` في الجذر، وعلى `.github/workflows` و`windows/` و`release-assets/` ضمن المصدر.
2. شغّل `npm ci` و`npm run build` والاختبارات المناسبة للتغيير. راجع الملفات قبل حفظها؛ لا ترفع `.env` أو `.vercel` أو `node_modules` أو `windows/dist` أو EXE أو مفاتيح التوقيع إلى Git.
3. انشر البناء الناجح على مشروع **abbeedo-tv-1.1** الحالي عبر Vercel، أو ادفع المصدر إلى `main` إذا كان **Settings → Git** يربط المشروع بالمستودع وفرع الإنتاج. تحقّق من الربط بدل إنشاء مشروع آخر.
4. إعدادات البناء: **Other** وNode.js **22**، والتثبيت `npm ci`، والبناء `npm run build`. جذر المشروع هو موضع `package.json` و`vercel.json`، والبناء يولّد `.vercel/output`.
5. بعد النشر تحقّق من المراجعة على الدومين ومن health والمسارات المذكورة أدناه. لا يُعد نجاح البناء المحلي أو معاينة READY إثباتًا لنشر الإنتاج.

خطوات Safari وCodespaces في [دليل الآيفون](IPHONE_DEPLOY_AR.md).

## أول إصدار تنزيلات والتحقق منه

1. افتح [Actions](https://github.com/abbeedo7/abbeedo-site/actions) وفعّل workflows إن طلب GitHub ذلك.
2. إذا لم تبدأ المهمة تلقائيًا بعد دفع المصدر، اختر **Publish application downloads → Run workflow → main → Run workflow** وانتظر النتيجة.
3. عند نجاحها، افتح [Releases](https://github.com/abbeedo7/abbeedo-site/releases) وتحقق من إصدار عام يحتوي:

   - `abbeedo-TV-Android.apk` — أندرويد 3.9.4 المرفق بعد مطابقة SHA-256؛ لا يُعاد بناؤه من هذه الحزمة.
   - `abbeedo-TV-Setup.exe` — مثبت Windows 1.2.0 مبني من المصدر.
   - `abbeedo-TV-Portable.exe` — Windows 1.2.0 المحمول في ملف واحد.
   - `releases.json` — الإصدارات والأحجام والبصمات.

يبقى الإصدار مسودة حتى رفع الملفات كلها. عند الفشل افتح سجل المهمة وأصلح السبب ثم أعد التنفيذ. لا تضف EXE إلى سجل Git لتجاوز المشكلة.

يقرأ الموقع البيان العام التالي دون مفتاح GitHub في Vercel:

https://github.com/abbeedo7/abbeedo-site/releases/latest/download/releases.json

إلى أن يتوفر إصدار عام صالح، قد يظهر `DOWNLOAD_UNAVAILABLE`. التفاصيل في [دليل الإصدارات](RELEASES_GITHUB_AR.md). نشر الموقع ونشر ملفات البرامج مساران مستقلان.

## الحفاظ على التخزين والتعافي

المخزن الخاص **متصل بالفعل**؛ عولجت استجابة `503 HOSTING_CONFIG` السابقة. احتفظ بمخزن `abbeedo-tv-private` وبياناته ومتغيرات البيئة ومفاتيح التشفير والجلسات. لا تستبدله بمخزن فارغ ولا تدوّر المفاتيح أثناء التحديث العادي.

إذا عاد خطأ `HOSTING_CONFIG`:

1. افتح **Storage** في المشروع الحالي وتحقق من استمرار اتصال المخزن الخاص نفسه ببيئة **Production**.
2. تأكد من توفر `BLOB_READ_WRITE_TOKEN` واتصال الموارد ومتغيرات البيئة الحالية. لا تطبع قيمها ولا تنسخها إلى GitHub أو الواجهة أو المحادثة.
3. افحص سجلات Vercel وأصلح الربط أو المتغير المفقود، ثم أعد النشر على المشروع نفسه.
4. افتح https://www.abbeedo.com/api/health وتحقق من **200** و`storage: true` و`mediaConfigured: true` قبل تجربة خدمات الحساب والمشاهدة.

احتفظ بإعداد Domains: `www.abbeedo.com` أصل رئيسي و`abbeedo.com` يحوّل إليه. بيانات المتصفح مرتبطة بهذا الأصل.

## التحقق بعد النشر

- افتح `/` و`/apps` و`/app` وتحقق من المراجعة الجديدة. الموقع يحمل اسم ابوناصر، والتطبيق يحمل اسم ابوناصر TV.
- على الآيفون، إضافة `/` للشاشة الرئيسية تحفظ اختصار الموقع، وإضافة `/app` تثبّت PWA التطبيق وشعاره. قد يلزم حذف الاختصار القديم وإضافته من المسار الصحيح لتجديد أيقونة iOS.
- بعد نجاح الإصدار، افتح `/api/releases` وجرّب `/downloads/android.apk` و`/downloads/windows.exe` و`/downloads/windows-portable.exe`. يجب أن تنتهي التنزيلات عند أصول إصدار المستودع في GitHub.
- اختبر دخول اشتراك مصرح باستخدامه وقائمته وتشغيله؛ health الناجح لا يثبت وحده نجاح حساب مزود فعلي.
- Windows يحتاج تثبيت **1.2.0** أول مرة لتفعيل المحدّث الأصلي. تحديث المحمول يستخدم Setup أيضًا. الملفات غير موقعة ولم يُختبر التثبيت أو التحديث على جهاز Windows فعلي.
- أندرويد يحتاج تثبيت **3.9.4** أول مرة لمسار التحديث الجديد؛ موافقة مثبت النظام وإذن المصادر غير المعروفة يظلان مطلوبين عند طلبهما.
- LG حزمة IPK حقيقية؛ Samsung حزمة WGT كاملة غير موقعة تحتاج شهادتي المالك author وdistributor ثم التوقيع والاختبار. راجع [دليل التلفزيون](TV_STORES_AR.md).

تحديث الموقع وPWA لا ينشئ حزمة Android أو Windows أو Samsung جديدة. مهمة التنزيلات تستثني `docs/**` و`README_AR.md`؛ تحديث APK يتطلب ملفًا جديدًا مطابقًا لبياناته. تختلف الترميزات وDRM والإشعارات والعمل في الخلفية حسب الجهاز والمصدر، ولم تُعتمد أجهزة التلفزيون أو المتاجر فعليًا.
